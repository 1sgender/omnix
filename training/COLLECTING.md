# Сбор живой речи для v0.2 (runbook)

Единственный блокер приёмки wake-word v0.2 — датасет живой речи
(training/README.md: ≥500 произнесений «Omni» от ≥20 дикторов, ≥10 ч
фонов, ≥200 трудных негативов). Ниже — как его закрыть без студии:
телефон, диктофон, пара вечеров.

## 1. Позитивы — фраза «Omni»

Записывайте так, как реально будет использоваться wake-word:

- **дистанция 0.5–3 м**, телефон на столе или в руке — не у рта;
- разная громкость и интонация: обычная речь, шёпот, вопрос, из другой
  комнаты; утром/вечером (голос меняется);
- варианты фразы: «omni», «омни», «omni, …», «hey omni», «omni are you
  there» — каждое произнесение отдельным файлом;
- **пауза ≥1 с до и после** фразы; обрезка не нужна — скрипт проверит
  длительность (0.3–3.0 с бракуется/принимается автоматически);
- удобно: 50 фраз за подход, файлы нумеруются диктофоном сами;
- один диктор = одна метка `--speaker` (латиницей: `ivan`, `maria`, …).
  ЗАПИСИ ОДНОГО ДИКТОРА — ВСЕГДА ОДИН СПЛИТ (train ИЛИ test), иначе
  нарушится speaker-disjoint и метрики станут фиктивными;
- 2–4 диктора отложите целиком в `--split test` (тестовые дикторы,
  которых модель не видела при обучении).

Экспорт из диктофона: **WAV** (m4a/ogg скрипт не читает). 16 кГц mono
идеально; любое разрешение конвертируется автоматически.

## 2. Негативы

- обычная речь (разговоры, ТВ, подкасты) — длинные записи до 10 минут;
- **трудные негативы** — отдельно, файл в имени со словом-маркером:
  `hard_many_01.wav`, `honey_02.wav`, `умный_03.wav`, `тони_04.wav`
  (минимум 200; скрипт считает их по имени);
- **фон** — длинные записи (≥30 с, лучше по 5–10 минут): тишина комнат,
  офис, улица, кухня, ТВ-шум. Суммарно ≥10 часов (считаются только
  файлы ≥30 с).

## 3. Заливка и статус

```bash
# проверка партии без копирования
python3 training/collect_live.py add ~/downloads/batch1 \
    --speaker ivan --kind positive --dry

# заливка
python3 training/collect_live.py add ~/downloads/batch1 \
    --speaker ivan --kind positive --split train

# статус датасета против целей v0.2
python3 training/collect_live.py report
```

Скрипт нормализует всё в контракт пайплайна (16 кГц mono int16),
бракует неформат, предупреждает о клиппинге и тишине, ведёт манифест
`training/collect_*.csv`.

## 4. Когда report зелёный

Пайплайн v0.1 без изменений (данные едут тем же путём):

```bash
python3 training/make_features.py   # аугментация + фичи (живые данные внутри)
python3 training/train_omni.py      # обучение, подбор порога, экспорт ONNX
python3 training/eval_streaming.py  # стриминговый eval
python3 training/verify_model.py --model <onnx>   # контракт перед заменой в APK
```

Дальше — критерии приёмки фазы 2 (training/README.md): verify зелёный,
FRR не хуже `hey_jarvis` при том же FAR, прогон
`device-validation/06-wakeword-metrics.sh` на устройстве, обновление
NOTICE/SHA256SUMS и удаление фолбэка из assets.
