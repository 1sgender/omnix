# Нагрузочный тест OMNIX-сервера

Скрипт `loadtest.py` — только стандартная библиотека Python 3, без зависимостей.
Шлёт N одновременных запросов на `/v1/health`, `/v1/license/validate` и (с флагом `--ai`) `/v1/ai/execute`,
считает долю 2xx / 429 / 503 / прочих ошибок и задержки p50 / p95 / p99.

## ВАЖНО: где можно запускать

- **НЕ запускать на боевом сервере.** Нагрузка занимает пул соединений БД и лимиты пользователей.
- **НЕ запускать с `--ai` против настоящих платных/квотных провайдеров** (Gemini, Claude, Groq):
  каждый запрос тратит квоту и деньги. Для `--ai` поднимайте тестовый сервер с фейковыми провайдерами.
- Скрипт по умолчанию отказывается работать с не локальным адресом; для своего тестового стенда нужен `--allow-remote`.

## Запуск

```powershell
$env:OMNIX_LOADTEST_TOKEN = "тестовый-токен"
python tools/loadtest/loadtest.py --base-url http://localhost:8090 -n 200 -c 50
python tools/loadtest/loadtest.py --ai -n 40 -c 10
```

Параметры: `--base-url` (по умолчанию `http://localhost:8090`), `-n` запросов на сценарий, `-c` одновременных,
`--timeout` секунд, `--ai`, `--allow-remote`. Токен берётся из переменной `OMNIX_LOADTEST_TOKEN`
(в аргументах командной строки его нет, чтобы не попадал в историю).

## Как читать результат

- `503` вместе с `Retry-After` и кодом `SERVER_BUSY` — штатный быстрый отказ ограничителя одновременных запросов
  (`OMNIX_MAX_AI_IN_FLIGHT`, `OMNIX_MAX_STT_IN_FLIGHT`, `OMNIX_MAX_IN_FLIGHT`). Это не сбой.
- `429` — лимит клиента (`RATE_LIMITED`/`QUOTA_EXCEEDED`).
- «другие 5xx» и «сеть/таймаут» — реальные проблемы: смотрите логи сервера.
- `/v1/health` должен оставаться быстрым (единицы мс) даже когда ИИ-эндпоинты отвечают 503.
- На фиктивные тела `license/validate` сервер отвечает 4xx — для проверки пропускной способности это нормально.
