# Venice AI: провайдер только для админа

Venice (OpenAI-совместимый API, `https://api.venice.ai/api/v1`) подключён как
провайдер исключительно для владельца. Ни у кого другого нет доступа ни к ключу,
ни к моделям: ни через приложение, ни через API сервера, ни через автоматический
выбор модели.

## Как включить

1. На VPS добавьте ключ в `/opt/omnix/deploy/.env.production` (файл вне
   репозитория, в git его нет):

   ```
   VENICE_API_KEY=<ключ Venice>
   # необязательно: админ-ключ Venice, нужен только для просмотра лимитов и баланса
   VENICE_ADMIN_API_KEY=<админ-ключ Venice>
   # необязательно: предохранители расхода (по умолчанию 20 и 1024)
   VENICE_REQUESTS_PER_MINUTE=20
   VENICE_MAX_OUTPUT_TOKENS=1024
   ```

2. Перезапустите контейнер: `docker compose -f deploy/docker-compose.production.yml up -d omnix-server`
   (или `docker restart omnix-server`).
3. Админом считается аккаунт из `ADMIN_ACCOUNT_IDS` (тот же механизм, что у
   «Тест моделей (админ)»). Там же, в приложении: Настройки, ИИ-модель, блок
   «Venice AI (только админ)».

Пустой `VENICE_API_KEY` означает, что провайдер выключен: список моделей и чат
недоступны никому, админ видит понятное сообщение.

## Как устроена защита

* Ключ читается только из окружения сервера. В приложении, БД, ответах API и
  логах его нет: `LogSanitizer` маскирует `VENICE_*_KEY_…`, клиент вычищает
  точное значение ключа из любых строк, которые возвращает или логирует.
  Адрес API из окружения не настраивается, чтобы ключ нельзя было отправить на
  чужой хост.
* Проверка админа одна и та же везде: `AdminModelAccess.isAdmin(accountId)`
  (роль определяет сервер по `ADMIN_ACCOUNT_IDS`, клиент не может назначить себя).
  Для не-админа любого тарифа (Free, Pro, omnix), для запроса без токена и для
  статического токена без аккаунта пути `/v1/venice/…` не существуют: ответ как
  у любого неизвестного пути (404).
* Venice не входит в `ProviderManager` и `ProviderId`, поэтому AUTO/Flash/Pro и
  запасные цепочки его не видят. В `/v1/ai/execute` поле `adminProvider` вида
  `venice:<модель>` действует только для админа; у остальных оно игнорируется,
  и запрос обслуживается обычным путём.

## Эндпоинты (только админ)

* `GET /v1/venice/models`: текстовые модели (id, контекст, цена USD за 1M
  токенов, privacy `private` / `anonymized` / `e2ee`, признак uncensored); кэш 10 минут.
* `GET /v1/venice/limits`: наши предохранители, расход с запуска сервера
  (запросы, токены, USD), `x-ratelimit-*` из последнего ответа Venice и ответ
  `GET /api_keys/rate_limits` (лимиты, баланс). Без админ-ключа Venice вернёт
  `VENICE_ADMIN_KEY_REQUIRED`: «Нужен админ-ключ Venice для просмотра лимитов».
* Чат: обычный `POST /v1/ai/execute` с `adminProvider = "venice:<id модели>"`.
  Потоковой выдачи в проекте нет, поэтому и здесь вызов обычный (`stream=false`).

## Лимиты и расход

* Повтор при 429/500/502/503/504 и сетевых сбоях: экспоненциально (0,5 с, 1 с, 2 с),
  не раньше сброса лимита из `x-ratelimit-reset*` / `Retry-After`; если сброс
  дальше 20 с, повтор не делается. 400/401/402/403/404/422 не повторяются.
* Бюджет ошибок Venice (50 неудачных запросов за 30 с на модель): мы
  останавливаемся на 40 и не доводим до блокировки модели.
* По умолчанию 20 запросов в минуту и 1024 токена ответа (`VENICE_REQUESTS_PER_MINUTE`,
  `VENICE_MAX_OUTPUT_TOKENS`).
* Токены и стоимость берутся из `usage` ответа и цены модели; в лог и метрики
  (`venice_requests_total`, `venice_input_tokens_total`, `venice_output_tokens_total`,
  `venice_cost_microusd_total`) идут только числа, без текста запросов и без ключа.
* Часть моделей без цензуры (`venice-uncensored-1-2`, `gemma-4-uncensored`,
  `…-uncensored`, `e2ee-…-abliterated`): в списке они помечены, ответы
  подписываются как «Venice · <модель>».
