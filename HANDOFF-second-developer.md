Кто написал: агент, который ведёт это репо вместе с владельцем (1sgender).
Цель документа: чтобы мы работали параллельно и **без единого конфликта**.
Прочитайте целиком перед первым коммитом — тут 5 минут чтения.

## 1. Проект в двух словах

- **OMNIX** — Android-приложение (Kotlin, Jetpack Compose Material3, MVVM + Hilt).
- Архитектура: `VoiceInteractionOrchestrator` → фазы → `OmnixViewModel` → **единственный** `OmnixUiState` → экраны.
- ИИ: локальная модель на устройстве (MediaPipe/LiteRT) + облачный fallback.
- Репо: `github.com/1sgender/omnix`. Доступ вам выдаёт владелец — он добавит ваш
  аккаунт как коллаборатора GitHub. **Работайте под своим аккаунтом**, общих
  токенов не существует и не будет (это принципиально).

## 2. ГЛАВНОЕ ПРАВИЛО ПРЯМО СЕЙЧАС — НЕ НАРУШАТЬ

> **Авто-релизы OTA заморожены.** Приложение обновится **одним** релизом после
> завершения ВСЕГО интерфейса, не по каждому изменению (решение владельца
> от 2026-09-24, повторено дважды — это жёсткое правило).

Механика: репо-переменная Actions `OTA_AUTO_RELEASE = false` + guard в
`.github/workflows/release.yml`. Поэтому:

- **НЕ** включайте переменную, **НЕ** правьте `release.yml` / `build.yml`,
  **НЕ** запускайте Release вручную — всё это только по явному «да» владельца.
- Мерджи в main делать **можно и нужно** — CI валидирует каждый PR, просто
  ничего не публикуется в OTA. Staging стоит на **v135 (sha 5e93559)** и не
  сдвинется до финального релиза — это нормально, так задумано.

## 3. Как работаю я (чтобы вы понимали, с чем имеете дело)

1. Одна задача = одна ветка (`kebab-case`, например `core-layers-amplitude`)
   → коммиты → push → **PR в main**. Прямых пушей в main не делаю никогда.
2. PR держится открытым до **зелёного CI** (Build + Supply Chain Security),
   только потом мердж. Метод мерджа — **merge commit** (не squash).
3. Перед каждым PR объявляю владельцу точное время завершения (Ташкент, UTC+5),
   при сбое/флейке сразу пересчитываю и сообщаю. Это моё обязательство перед
   владельцем; от вас такого не требуется, но «сказал время — сдержи» здесь
   ценится.
4. Каждый PR обновляет `CHANGELOG.md` (секция `[Unreleased]`, пункты
   `Added/Changed` — по-русски, как в существующих записях).
5. Стиль коммитов: `type(scope): описание` по-английски, императив, с
   развёрнутым body. Пример из репо: `ci(release): freeze OTA auto-release
   behind OTA_AUTO_RELEASE variable`.
6. После мерджа я слежу за билдами main и staging (сейчас — только билды).

### 4.3 Протокол координации (пять пунктов)

1. **До старта** задачи сообщите владельцу список файлов/модулей, которые
   затронете. Владелец синхронизирует нас. Однажды распределённая зона —
   закреплена за человеком.
2. Ветки короткоживущие: дни, не недели. Долгая ветка = гарантированный
   конфликт при мердже.
3. Перед пушем и перед мерджем: `git fetch origin && git rebase origin/main`.
   Конфликты решаются маленькими — это нормально, разруливайте у себя,
   а не в main.
4. `CHANGELOG.md` — единственный файл, где конфликт случится почти наверняка
   (пишут все). Правило: свой пункт добавляйте **в конец** секции
   `[Unreleased]` и ребейтесь перед мерджем; разрешение тривиальное.
5. Force-push только в **свою** ветку и только если никто её не пуллил.
   Никогда — в main.

## 5. Технические конвенции кодовой базы (выбраны не на ровном месте)

- Иконки: `androidx.compose.material3.Icon` — **не** `material.Icon`
  (просто не резолвится).
- `delay()` принимает **Long**: `x.coerceAtLeast(10)` даёт Int → compile error.
  Всегда `.toLong()`.
- В backtick-именах юнит-тестов **запрещены точки** (detekt): используйте
  `«с пробелом и тире»`, как в существующих тестах.
- detekt (`config/detekt/detekt.yml`): complexity / MagicNumber / MaxLineLength
  / ForbiddenComment выключены; **UnusedPrivateMember включён** — мёртвый
  приватный код уронит CI.
- Чистая логика (мапперы, слои, latch-и, мониторы) покрывается **JVM-тестами**
  без Android-зависимостей — по примеру `CoreLayersTest`, `AmplitudeRingTest`.
- Новые UI-сигналы проводятся через `OmnixUiState` (один источник истины),
  параллельных стейт-хранилищ не заводить.
- Дизайн-матрица ядра: монохром; один главный сигнал на кольце
  (глиф > дуга > амплитуда > форма); красный — только ERROR; бейджи
  ортогональны (CLOUD / WIFI_OFF); reduced-motion гасит амплитудный слой.
- `web/admin/` собирается npm-билдом в resources — это **намеренно**, не
  «случайно закоммиченный мусор».
